Program: [#1](https://github.com/tommy-ca/chronforge/issues/1)

Qstack owns ChronForge quant-development composition and verification contracts while delegating generic software-engineering mechanics to upstream pstack. ChronForge owns code, tests, issues, PRs, and project/runtime evidence. OpenSpec owns durable intent artifacts. Qorch owns later quant-research orchestration.

## OpenSpec intent rule

Every material phase/capability implementation follows:

```text
proposal -> specs -> design -> ADR review -> tasks
  -> merge intent artifacts
  -> qstack profile selection
  -> pstack/orch execution
  -> ChronForge leaf PRs
  -> join receipt
  -> merge implementation
  -> strict OpenSpec verify/archive
```

Read-only investigation may proceed without a new product change. Emergency fixes require explicit exception plus retrospective OpenSpec reconciliation.

## Join rule

Leaf issues may run in parallel where dependencies permit, but only the join issue advances the phase:

```text
D0 -> #14
D1 -> #19
D2 -> #24
D3 -> #29
```

Every join receipt must be revision-specific, name its qstack semantic/profile revision, list acceptance IDs, include verification commands/results, and distinguish Static/Metadata/formal evidence from Runtime/PAPER/LIVE evidence.

## Research handoff

D3.J emits `SoftwareArtifactRef`, `RunReceipt`, and `DeterminismReceipt`. Quant research then moves to qstack `qorch`:

```text
ChronForge verified artifact
  -> qorch ResearchProgram/Study artifact edge
  -> qorch program-ready
  -> agent/SearchRunner research
  -> ChronForge RunReceipt
  -> qorch validation/candidate/promotion evidence
```

Qorch does not mirror ChronForge branches, worktrees, PR state, or development worker assignments.

## Evidence honesty

- READY means graph readiness, not Runtime PASS.
- Static/Metadata/CI PASS does not imply PAPER/LIVE PASS.
- Timeout != PASS.
- Optional issue existence does not imply capability selection.
